Wuji Hand 2 · pen spinning (转笔) · project walkthrough

The penspin-graph project, explained step by step

Each of the 11 stages: what it does, the formula behind it, and what Wuji's official method does instead.
Sources: penspin-graph repo (src/penspin_graph/, measured results in runs/full3/) · wuji-mjlab v2026.10.22 (src/wuji_mjlab/tasks/pen_spin/, deploy/pen_spin/). All results are from simulation.
❓ The question in plain words
Wuji gives 40 recorded pen-spinning clips and a policy (策略) that follows one clip at a time. How did this project turn that into a controller that starts from any hand state and keeps the pen spinning? And at every stage, what differs from Wuji's official method?
🎯 Where we will end up
  1. Every frame becomes a point: $\bff_t=\mathbf w\odot(\bx_t-\boldsymbol\mu)/\boldsymbol\sigma\in\mathbb R^{67}$.
  2. Frames are linked inside each clip. New jumps $u\to v$ are added when $C(u,v)=\frac1\delta\sum_{j}\lambda_j\lVert\bff_{u+1+j}-\bff_{v+j}\rVert\le 6$, or when a clip's final hold can blend into another clip's start.
  3. A jump is kept only if it is physically gentle (blend $b=\clip(\lceil\Delta q_{\max}/(\omega_{\max}\Delta t)-1\rceil,2,10)$) and if Wuji's own policy, $\bq^{\text{target}}=\bq^{\text{ref}}+\operatorname{EMA}(\clip(0.5\,\ba))$, executes it in simulation about as well as the original clip.
  4. 38,624 jumps pass. They connect 15,215 frames (59%) into a core the hand never has to leave.
  5. From any state: nearest frame $v^*=\arg\min_v\lVert\bff(s)-\bff_v\rVert$, shortest path into a verified loop, then circle it.

⚠ Look-alike symbols
  • $\bq$ is always joint angles. Quaternions are $\brho$. (The code calls both "q".)
  • $v$ is a frame (node). The speed limit is $\omega_{\max}$, not "$v_{\max}$".
  • $\delta$ (step unit, a feature distance) ≠ $\Delta t$ (0.02 s) ≠ $\Delta q_{\max}$ (a joint gap in rad).
  • $C(u,v)$ = how different two continuations are. $c(e)=25+10\,C$ = what an edge costs the planner. They are related but not the same.
  • $K=12$ neighbours ≠ $k$ = control tick.

1 Load the clips and move everything into the wrist frame 读取数据 · 手腕坐标系

✍ What the code writes (src/penspin_graph/data/clips.py)

Step 1.1 The raw data of one frame
$$\text{NPZ frame }t:\quad \bq_t\in\mathbb R^{20},\quad (\mathbf t^{w}_t,\ \brho^{w}_t),\quad (\bp^{\text{world}}_t,\ \brho^{\text{world}}_t),\quad \bl^{\text{world}}_{t}\in\mathbb R^{21\times3}$$

This is what Wuji's 40 clips contain: joint angles, the wrist pose, the pen pose and the link positions. Everything except the joints is in the capture world frame. Frames are 0.02 s apart. In total: 5 motion groups, 25,885 frames (8.6 min).

Step 1.2 Pen position into the wrist frame R1
$$\bp_t=\hl{R(\brho^{w}_t)^{\top}}\big(\bp^{\text{world}}_t-\hl{\mathbf t^{w}_t}\big)$$

First subtract the wrist origin. Then undo the wrist rotation. After this, the pen position no longer depends on where the hand stood during the recording. The same rule moves the 21 link positions into the wrist frame.

Step 1.3 Pen orientation into the wrist frame R2
$$\brho_t=\hl{(\brho^{w}_t)^{-1}}\otimes\brho^{\text{world}}_t$$

A quaternion is "re-based" by multiplying with the inverse of the frame's quaternion. Checked numerically: R1 and R2 reproduce the stored wrist-local arrays exactly.

Step 1.4 The shaft direction R2
$$\bn_t=R(\brho_t)\,\hl{\mathbf e_x},\qquad \mathbf e_x=(1,0,0)^{\top}$$

In the pen model the long axis is the pen's own $x$ axis. For spinning, only where the shaft points matters. Roll about the shaft is invisible to the task, and Wuji's policy ignores it too.

Step 1.5 Velocities by finite differences R5 HIDDEN STEP
$$\dq_t=\frac{\bq_{\hl{t+1}}-\bq_t}{\Delta t},\qquad \bom_t=\frac{\log\!\big(\brho_t^{-1}\otimes\brho_{\hl{t+1}}\big)}{\Delta t}$$

The clips store no velocities, so they are computed from the next frame. The pen's angular velocity is the rotation from frame $t$ to $t+1$, written as a rotation vector, divided by $\Delta t$. Hidden detail: the last frame has no next frame, so the code copies the previous value.

Step 1.6 Mark resting frames
$$s_t=\Big[\max_i|\dot q_{t,i}|\hl{<0.2}\ \tfrac{\text{rad}}{\text{s}}\Big]\ \wedge\ \Big[\lVert\bom_t\rVert\hl{<0.3}\ \tfrac{\text{rad}}{\text{s}}\Big]$$

Every clip ends with a hold (静止段): the hand pinches the pen and nothing moves. The median hold lasts 2.0 s. The first frame of this trailing hold is called the clip's active end. Stage 3 keeps holds out of normal jumps. Stage 4 uses holds on purpose.

🔢 Example (1D)
Clip A: wrist at $x=0.30$ m, pen at $x=0.37$ m $\Rightarrow$ local $0.07$ m. Clip B: wrist at $x=0.50$ m, pen at $x=0.57$ m $\Rightarrow$ local $0.07$ m. In the wrist frame the two states are identical. In the world frame they look 20 cm apart. Velocity: a joint goes from $0.40$ to $0.43$ rad in one frame $\Rightarrow 0.03/0.02=1.5$ rad/s.

2 Turn every frame into one 67-D point 嵌入 · 高维向量点

✍ What the code writes (src/penspin_graph/features/featurizer.py)
for b in self.active_blocks:
    z = (raw[b] - self.mean[b]) / self.std[b]      # z-score per dimension
    parts.append(self.block_weights[b] * z)        # times the block weight
return np.concatenate(parts, axis=1)               # 67 numbers per frame
Step 2.1 Stack seven blocks
$$\bx_t=\big[\ \bq_t\ ;\ \dq_t\ ;\ \bp_t\ ;\ \bn_t\ ;\ \dot{\bp}_t\ ;\ \bom_t\ ;\ \bl^{\text{tips}}_t\ \big]$$

These numbers describe what the hand and pen are doing right now. Shape check: $20+20+3+3+3+3+15=67$.

Step 2.2 z-score each dimension R3
$$z_{t,i}=\frac{x_{t,i}-\hl{\mu_i}}{\hl{\sigma_i}},\qquad \mu_i,\sigma_i\ \text{over all 25,885 frames},\quad \sigma_i\ge10^{-3}$$

The blocks have different units. Joint angles vary by 0.08–0.61 rad. Pen positions vary by only 1.4–2.1 cm. Without the z-score, a metre-valued block would vanish next to a radian-valued block.

Step 2.3 Multiply by a block weight
$$f_{t,i}=\hl{w_{b(i)}}\,z_{t,i},\qquad w=\{\bq\!:1,\ \dq\!:0.4,\ \bp\!:2,\ \bn\!:2,\ \dot\bp\!:0.4,\ \bom\!:0.4,\ \text{tips}\!:1\}$$

The weights say what "similar" means for pen spinning. The pen pose counts most, poses count normally, and velocities count a little.

Step 2.4 Distance between two frames R4
$$d(t,t')=\lVert\bff_t-\bff_{t'}\rVert=\sqrt{\textstyle\sum_{b}\hl{w_b^{2}}\,\lVert\bz_{t,b}-\bz_{t',b}\rVert^2}$$

The weight is squared inside the distance. So pen position, with weight 2, counts 4× per dimension compared with one joint angle.

Step 2.5 A natural unit: the step unit $\delta$ R6
$$\delta=\operatorname*{median}_{t}\ \lVert\bff_{t+1}-\bff_t\rVert=\hl{0.565},\qquad \text{report every distance as } d/\delta$$

$d/\delta=1$ means "as different as one typical 50 Hz step". This makes every threshold readable. The median ignores the many tiny steps inside holds (10th percentile 0.08) and the few fast flicks (90th percentile 1.53).

🔢 Example
Joint: $\mu=0.40$, $\sigma=0.20$ rad. Frame A at 0.60 rad gives $z=1.0$. Frame B at 0.50 rad gives $z=0.5$. Contribution to $d^2$: $1^2\cdot0.5^2=0.25$.
Pen $x$: $\sigma=2$ cm. A at 7 cm, B at 9 cm, so $\Delta z=1.0$. Contribution: $2^2\cdot1.0^2=4$.
So a 2 cm pen gap counts 16× more than a 0.1 rad joint gap.
💡 Coder's view
f = w * (x - mu) / sigma and d = np.linalg.norm(f[a] - f[b]) / delta. This is the same normalisation you would apply before kNN in any machine-learning pipeline. The only extra choice is the block weights.

3 Propose jumps: kNN + window matching 候选跳转 · k近邻 + 窗口匹配

✍ What the code writes (src/penspin_graph/graph/motion_graph.py)
q = F[u + 1]                                          # query: the frame we would play next

Step 3.1 What a jump means
$$\text{recorded: } u\to u+1\to u+2\to\cdots\qquad\text{jump: } u\to\hl{v}\to v+1\to\cdots$$

A jump replaces "the rest of this clip" with "the rest of another clip (or another moment of this clip)". Frame $v$ takes the place of $u+1$.

Step 3.2 Match the next frame, not the current one HIDDEN STEP
$$\text{want}\quad \bff_v\approx\bff_{\hl{u+1}}\qquad(\text{not }\bff_u)$$

$v$ is what the hand will be asked to do next. So it must look like what the hand would have done next, which is $u+1$. Your original idea said "find the most related point except its own $t+1$". This step makes it precise.

Step 3.3 Ask for the $K=12$ nearest frames R15
$$\mathcal V_K(u)=\operatorname{KNN}_{12}\big(\bff_{u+1}\big)\ \ \text{restricted to }\hl{\text{allowed }v}$$

Allowed means: (a) both $u$ and $v$ are moving, not resting ($s=0$); (b) $v$ has at least 4 more frames after it; (c) $v$ is in another clip, or in the same clip at least 50 frames (1 s) away from $u$.

Step 3.4 Window cost R7
$$C(u,v)=\frac{1}{\delta}\sum_{j=0}^{W-1}\hl{\lambda_j}\,\big\lVert\bff_{u+1+j}-\bff_{v+j}\big\rVert,\qquad \lambda_j=\frac{0.8^{\,j}}{\sum_{i=0}^{W-1}0.8^{\,i}}$$

One similar frame is not enough. A pen moving up and a pen moving down can pass through the same pose. Comparing the next $W=5$ frames (0.1 s) checks that both continuations are about to do the same thing. With $W=5$: $\lambda=(0.298,\ 0.238,\ 0.190,\ 0.152,\ 0.122)$, so earlier frames count more because they are executed first.

Step 3.5 Keep the cheap ones
$$\text{keep } u\to v\quad\text{if}\quad C(u,v)\le\hl{6}$$

6 step units still allows clearly different clips to connect. Stages 5 and 7 then decide which of them the hand can really execute. Result: 101,934 candidates. Of all jumps that later pass simulation (stage 7), 26,803 cross between clips and 11,821 stay inside one clip.

🔢 Example
Distances over the window, in step units: $2,\,2,\,3,\,3,\,4$. $C=0.298\cdot2+0.238\cdot2+0.190\cdot3+0.152\cdot3+0.122\cdot4=2.59\le6\Rightarrow$ kept. Check on real data: recomputing $C$ by hand for a stored jump gives $1.5997$, the same as the stored value.
⚠ Two rules learned the hard way
  • Holds are excluded. All resting frames look almost identical. Without this rule the cheapest "jumps" are hold → hold inside one clip. They cost about 0, always pass, and are useless.
  • Same-clip jumps need a 1 s gap. Otherwise $u\to u+2$ would count as a jump. A jump back in time inside a continuous-spin clip is the most natural way to repeat a turn.

4 Chain tricks through the resting grasp 动作衔接 · 静止抓握

✍ What the code writes (MotionGraph.propose_rest_transitions)
# u = first hold frame of clip a,  v = first moving frame of clip b
u = self.node_id(a, min(int(self.active_end[a]), int(self.episode_lengths[a]) - 1))
v = self.node_id(b, self.first_moving_frame(b))
if dpos > max_pen_pos_m or dax > max_pen_axis_rad:

Step 4.1 The problem, measured
$$\operatorname*{median}_{\text{clips}}\ \Big(\operatorname*{median}_{t}\ \min_{|t'-t|\ge 50}\ \frac{d(t,t')}{\delta}\Big)=\hl{10.6}\ \ (\text{range }6.9\text{–}13.3)\ >\ 6$$

Inside one clip, the closest frame at least 1 s away is usually more than 10 step units away. So the full state is not periodic: the fingers re-grasp differently on every turn. Stage 3 alone therefore produced only tiny loops. The largest region the hand could stay in forever was just 670 frames.

Step 4.2 The state all clips share
$$u_a=\text{first hold frame of clip }a,\qquad v_b=\text{first moving frame of clip }b\ \ (b\ne a)$$

Every clip ends in a resting pinch grasp, and every clip starts from a similar calm grasp. This is the natural "hub" for chaining one trick into another.

Step 4.3 The pen must already be close R10
$$e^{\text{pos}}=\lVert\bp_{u_a}-\bp_{v_b}\rVert\le\hl{6\ \text{cm}},\qquad e^{\text{ax}}=\arccos\big(\bn_{u_a}\cdot\bn_{v_b}\big)\le\hl{60^\circ}$$

During the blend the fingers may re-shape the grasp, but the pen should not have to travel. The next clip's reference expects the pen where its first frame has it.

Step 4.4a Speed during a blend of $b$ frames
$$\text{joint speed}=\frac{\Delta q_{\max}}{(\hl{b+1})\,\Delta t},\qquad \Delta q_{\max}=\max_i|q_{v_b,i}-q_{u_a,i}|$$

$b$ inserted frames split the gap into $b+1$ equal steps of $\Delta t$ each.

Step 4.4b Require a slow speed (3 rad/s)
$$\frac{\Delta q_{\max}}{(b+1)\,\Delta t}\le\hl{3}\ \tfrac{\text{rad}}{\text{s}}$$

A hold-to-start blend re-grasps the pen, so it is done slowly on purpose. This is about half of the normal limit used in stage 5.

Step 4.4c Solve for $b+1$
$$\hl{b+1}\ \ge\ \frac{\Delta q_{\max}}{3\,\Delta t}$$

Multiply both sides by $(b+1)/3$. It is positive, so the inequality keeps its direction: $\frac{\Delta q_{\max}}{3\Delta t}\le b+1$. Read from right to left, that is the line above.

Step 4.4d Solve for $b$, then take the smallest integer R8
$$b\ \ge\ \frac{\Delta q_{\max}}{3\,\Delta t}\hl{-1}\qquad\Longrightarrow\qquad b=\hl{\Big\lceil}\frac{\Delta q_{\max}}{3\,\Delta t}-1\hl{\Big\rceil}$$

$b$ must be a whole number of frames. The smallest whole number that is not below the bound is its ceiling.

Step 4.4e Never shorter than 0.5 s, never longer than 1 s
$$b\ \leftarrow\ \hl{\max}\big(b,\ 25\big),\qquad\text{reject if } b>50$$

Even a small gap gets 25 frames, so the policy has time to settle the grasp. A gap that needs more than 50 frames is too far to bridge.

🔢 Example
$\Delta q_{\max}=1.2$ rad: $1.2/(3\cdot0.02)-1=19$, so $\lceil19\rceil=19$ and $\max(19,25)=25$ frames (0.5 s). $\Delta q_{\max}=2.4$ rad: $2.4/0.06-1=39$, so 39 frames (0.78 s).
Step 4.5 What it gave
$$\text{600 proposed}\ \to\ \text{482 start in a real hold, tested}\ \to\ \hl{99\ \text{pass}}\ \ (98\ \text{after stage-8 pruning})$$

About 100 extra edges grew the region where the hand can stay forever from 670 to 15,215 frames (59% of the data). Normal jumps give variety inside one trick. Hold transitions chain one trick into another, like dance moves linked through a neutral pose. The other 118 proposals come from 6 clips without a real hold at the end and were not tested.

✍ What the code writes (src/penspin_graph/graph/kinematics.py)
dq     = np.abs(q_v - q_u).max(axis=1)
needed = np.ceil(dq / (limits.max_joint_vel * dt) - 1.0).astype(int)
blend  = np.clip(np.maximum(needed, limits.blend_frames), limits.blend_frames, limits.max_blend_frames)
speed_ok = dq / ((blend + 1) * dt) <= limits.max_joint_vel + 1e-9
Step 5.1 A speed limit taken from the data
$$\omega_{\max}=\hl{1.5}\times P_{99.9}\big(|\dot q|\big)=1.5\times3.87=5.81\ \tfrac{\text{rad}}{\text{s}}$$

While spinning, the recorded hand moved at up to 3.87 rad/s (99.9th percentile, 第99.9百分位数). The factor 1.5 leaves room, but it still rejects jumps that would need a violent snap.

Step 5.2 The minimal blend (same algebra as 4.4a–d)
$$b_{\text{need}}=\Big\lceil\frac{\Delta q_{\max}}{\hl{\omega_{\max}}\,\Delta t}-1\Big\rceil$$

Exactly steps 4.4a–4.4d, with 3 rad/s replaced by $\omega_{\max}$.

Step 5.3 Clip to the allowed range R11
$$b=\hl{\clip}\big(b_{\text{need}},\ 2,\ 10\big)$$

Every jump gets at least 2 smoothing frames. No jump may take more than 10 frames (0.2 s), because a long blend leaves the recorded motion for too long.

Step 5.4 Re-check the speed after clipping
$$\text{ok}_{\text{speed}}\iff\frac{\Delta q_{\max}}{(\hl{b}+1)\,\Delta t}\le\omega_{\max}$$

This can only fail when step 5.3 cut $b$ down to 10. Then even the longest allowed blend is too fast, and the jump is dropped.

Step 5.5 Joint limits: checking the two ends is enough HIDDEN STEP
$$l=(1-\gamma)\hl{l}+\gamma\hl{l}\ \le\ (1-\gamma)\,q_u+\gamma\,q_v\ \le\ (1-\gamma)\hl{h}+\gamma\hl{h}=h,\qquad \gamma\in[0,1]$$

If both end poses are inside the limits $[l,h]$, every straight-line blend between them is inside too. So the code checks only $\bq_u$ and $\bq_v$.

Step 5.6 The pen cannot teleport R10
$$e^{\text{pos}}=\lVert\bp_{\hl{u+1}}-\bp_v\rVert\le\tau_{\text{pos}}(b),\qquad \tau_{\text{pos}}(b)=\min\big(2\,\text{cm}\cdot(1+0.5\,(b-2)),\ 6\,\text{cm}\big)$$ $$e^{\text{ax}}=\arccos\big(\bn_{u+1}\cdot\bn_v\big)\le\tau_{\text{ax}}(b),\qquad \tau_{\text{ax}}(b)=\min\big(20^\circ\cdot(1+0.5\,(b-2)),\ 45^\circ\big)$$

The data says the pen will be at $\bp_{u+1}$. The jump pretends it is at $\bp_v$. The gap must be small. A longer blend gives the policy more time to move the pen, so the tolerance grows with $b$ up to a cap.

Step 5.7 Build the blended frames R9
$$\gamma_i=\frac{i}{b+1},\quad \bq^{(i)}=(1-\gamma_i)\,\bq_u+\gamma_i\,\bq_v,\quad \bp^{(i)}=(1-\gamma_i)\,\bp_u+\gamma_i\,\bp_v,\quad \brho^{(i)}=\operatorname{slerp}(\brho_u,\brho_v,\gamma_i)$$

For $i=1,\dots,b$. Joints, pen position and link positions are interpolated in a straight line. The pen quaternion uses slerp, so it stays a valid rotation.

🔢 Example
$\Delta q_{\max}=0.5$ rad: $0.5/(5.81\cdot0.02)-1=3.30$, so $b_{\text{need}}=\lceil3.30\rceil=4$ and $b=\clip(4,2,10)=4$. Speed: $0.5/(5\cdot0.02)=5.0\le5.81$ ✓. Tolerances at $b=4$: $\tau_{\text{pos}}=2\cdot(1+0.5\cdot2)=4$ cm and $\tau_{\text{ax}}=40^\circ$. Blend fractions: $\gamma=0.2,\,0.4,\,0.6,\,0.8$.
Real data: 5,403 proposals removed. Among validated jumps, blends of 2/3/4/5/6 frames occur 31,025 / 5,348 / 1,854 / 289 / 10 times.

6 The shared part: Wuji's tracking policy 共用部分 · 官方跟踪策略

✍ What the code writes (src/penspin_graph/sim/controller.py, copied from deploy/pen_spin)

Step 6.1 The observation (155 numbers)
$$\bo_k=\big[\,\underbrace{\bq^{\text{ref}}_k,\ \be^{\text{ref}}_k,\ \bl^{\text{ref}}_k}_{\text{command: }20+6+63\,=\,89},\ \bq_k,\ \hl{0.25}\,\dq_k,\ \be_k,\ \ba_{k-1}\,\big]\in\mathbb R^{155}$$

The policy sees the reference frame (the command), the live hand state, the live pen, and its own last output. Shape check: $89+20+20+6+20=155$, the same as Wuji's obs_dim.

Step 6.2 The pen as two shaft points R16
$$\be^{\pm}=\bp\pm\hl{0.10}\,\bn,\qquad\text{each coordinate}\ \ \beta(x)=0.15\tanh(x/0.15)$$

Two points 10 cm along the shaft encode both position and direction in 6 numbers. The tanh keeps a lost pen from producing huge inputs: $0.03\to0.0296$ (almost unchanged), $0.12\to0.0996$ (squashed).

Step 6.3 Raw action
$$\ba_k=\hl{\pi_\theta}(\bo_k)\in\mathbb R^{20}$$

$\pi_\theta$ is an MLP (Multi-Layer Perceptron, 多层感知机) with hidden layers 1024-512-256, loaded from Wuji's ONNX (Open Neural Network Exchange, 开放神经网络交换格式) file. There is one file per motion group.

Step 6.4 Scale and clip R11
$$\br_k=\hl{\clip}\big(0.5\,\ba_k,\ -0.6,\ 0.6\big)$$

The policy is allowed to correct each joint by at most ±0.6 rad.

Step 6.5 Smooth over time R12
$$\rb_k=\hl{0.5}\,\br_k+0.5\,\rb_{k-1}$$

The EMA (Exponential Moving Average, 指数滑动平均) removes jitter between control ticks. That protects the real hand's motors.

Step 6.6 The joint target
$$\bq^{\text{target}}_k=\hl{\bq^{\text{ref}}_k}+\rb_k$$

The policy is a corrector around the reference. The hand's PD (Proportional-Derivative, 比例-微分) position actuators then track the target for 4 physics steps of 0.005 s, which gives 50 Hz control.

🔢 Example (one joint)
Reference 0.80 rad, raw output $a=2.0$: $r=\clip(1.0,-0.6,0.6)=0.6$; $\bar r_1=0.5\cdot0.6+0=0.30$; target $=1.10$ rad. If $a$ stays 2.0: $\bar r_2=0.5\cdot0.6+0.5\cdot0.30=0.45$, target $1.25$ rad, and $\bar r\to0.6$ in the limit.
💡 Meaning: two consequences used later
  • Any test of a reference must include the policy. Open-loop replay (no correction) drops the pen within about 0.2 s, even on the original clips. With the policy, the pen stays within about 1.1 cm of the reference on average. → stage 7.
  • The live joints can sit far from the reference while everything is fine. So "am I lost?" must be judged by the pen, not by the joints. → stage 9.

Step 7.1 One start state
$$\text{start}=\big(\bq_u,\ \dq_u,\ \bp_u,\ \brho_u,\ \dot\bp_u,\ \bom_u\big)$$

The hand and the pen are placed exactly as recorded at frame $u$. Both test runs start from this same state, so the comparison is fair.

Step 7.2 Two references from the same start
$$\mathcal R^{J}=\big[\,u,\ \underbrace{\star\cdots\star}_{b\ \text{blended}},\ \hl{v,\ v+1,\ \dots,\ v+H-1}\,\big],\qquad \mathcal R^{B}=\big[\,u,\ u+1,\ \dots,\ u+L\,\big]$$

$\mathcal R^J$ takes the jump. $\mathcal R^B$ (baseline) continues the original clip for the same length $L$. $H=40$ frames (0.8 s); hold jumps use 50.

Step 7.3 Errors after every tick R10
$$e^{\text{pos}}_k=\lVert\bp^{\text{sim}}_k-\bp^{\text{ref}}_k\rVert,\qquad e^{\text{ax}}_k=\arccos\big(\bn^{\text{sim}}_k\cdot\bn^{\text{ref}}_k\big)$$

Only the pen is judged. The pen is the task. The joints are free to deviate (stage 6).

Step 7.4 Fail fast, with Wuji's own thresholds
$$\text{fail}\iff\exists\,k:\ e^{\text{pos}}_k>\hl{5\ \text{cm}}\ \ \lor\ \ e^{\text{ax}}_k\ge\hl{60^\circ}$$

These are exactly the termination limits of Wuji's training environment. If Wuji would call it a failure, so do we.

Step 7.5 It must end well
$$\tfrac15\textstyle\sum_{\text{last }5}e^{\text{pos}}_k\le\hl{3\ \text{cm}},\qquad \tfrac15\sum_{\text{last }5}e^{\text{ax}}_k\le\hl{30^\circ}$$

Surviving is not enough. At the end of the test the pen must be back on its reference, ready for whatever comes next.

Step 7.6 No worse than the original clip
$$\overline{e^{\text{pos}}}\big(\mathcal R^{J}\big)\ \le\ \hl{1.5}\cdot\max\!\Big(\overline{e^{\text{pos}}}\big(\mathcal R^{B}\big),\ \hl{1\ \text{cm}}\Big)$$

The clips are retargeted human motion, so even they are not perfectly trackable. The fair question is: "is the jump about as executable as just continuing the clip?" The 1 cm floor stops a near-perfect baseline from making the test impossibly strict.

Real data: 40,208 jumps tested, 38,624 pass (96%), about 60 ms per jump on one CPU core. Hold jumps are harder: 482 tested, 99 pass. Most of their failures are the pen moving more than 5 cm (244).

8 Loops, the spinnable core and end-to-end pruning 环路 · 强连通核心 · 端到端剪枝

✍ What the code writes (src/penspin_graph/graph/loops.py, sim/verify.py)

Step 8.1 The graph and its edge costs
$$G=(V,E),\qquad c(t\to t+1)=1,\qquad c(u\to v)=\hl{25}+\hl{10}\,C(u,v)$$

$V$ = the 25,885 frames. $E$ = recorded steps plus validated jumps. With these costs a path's cost is roughly its number of frames, and every jump "costs" like 25 + 10C frames. So the search prefers to stay on recorded motion and jumps only when it must. Example: $C=2$ costs like 45 frames.

Step 8.2 Close a loop through a jump R13
$$\text{loop}(u\to v)=\underbrace{\big(v\rightsquigarrow u\big)}_{\text{Dijkstra}}\ +\ \hl{(u\to v)}$$

A single clip is a chain, so every loop needs at least one jump. For a jump $u\to v$, the cheapest path from $v$ back to $u$, followed by the jump itself, is the cheapest loop that uses this jump.

Step 8.3 Skip jumps that can never be on a loop R14 HIDDEN STEP
$$u\to v\ \text{is on a loop}\iff \operatorname{SCC}(u)=\operatorname{SCC}(v)\ \ \text{and}\ \ |\operatorname{SCC}(u)|>1$$

(⇒) If a loop contains both, each reaches the other, so they are in one SCC. (⇐) If they are in one SCC, a path $v\rightsquigarrow u$ exists, and adding the edge $u\to v$ closes a cycle. Computing SCCs once removes most Dijkstra calls.

Step 8.4 Score a loop by how much the pen turns R17
$$\Phi=\sum_{t}\hl{\angle\big(\brho_t,\brho_{t+1}\big)},\qquad\text{keep }\Phi\ge180^\circ,\ \ \text{rank by }\Phi/T$$

The loop search sums the small change of pen orientation between consecutive frames. This favours loops where the pen keeps moving. $\Phi$ includes roll about the shaft, so it is a generous score. Stage 11 reports the stricter shaft-only rotation $\Theta$ instead.

Step 8.5 Replay whole loops and prune what breaks them
$$\text{replay fails at tick }k^{*}\ \Rightarrow\ \text{reject the last jump in }\big[\,k^{*}-\hl{100},\ k^{*}\,\big]\ \Rightarrow\ \text{search again}$$

Each jump passed a 0.8 s local test. But small errors can add up over a 15 s loop. The local test is necessary, not sufficient. So the top 30 loops are replayed in full, the guilty jump is removed, and loops are searched again. This ran for 5 rounds.

🔢 Result
Largest SCC: 15,215 frames (59%), from which the hand never has to stop. 151 loops with Φ ≥ 180°. 16 of the top 30 complete a full lap end to end.
Best loop: 752 recorded frames plus blends = 16.4 s per lap, 9 jumps, 3 clips (02/clip_003, 03/clip_002, 03/clip_003). Shaft rotation Θ = 1,709° per lap ≈ 104°/s. Its jump edges cost 35–196, so the planner pays for 9 jumps but gains a loop that never ends.

The live state goes through the same featurizer as the data, so it can be compared with every recorded frame. On the real hand the pen pose comes from the camera, the same signal Wuji's deploy code uses.

Step 9.2 Find the nearest recorded frame R15

This is your original "find the closest point" step. If a frame inside the core (the 59% SCC) is almost as close, it is preferred, because from the core there is always a way to keep going.

Step 9.3 Plan into the loop, then circle it R13
$$\text{plan}=\hl{\operatorname{Dijkstra}\big(v^{*}\rightsquigarrow\mathcal L\big)},\ \ \text{then}\ \ \mathcal L,\ \mathcal L,\ \mathcal L,\dots$$

The path enters the best verified loop $\mathcal L$ at its cheapest frame. After that the controller replays the loop lap after lap, starting from the entry frame.

Step 9.4 Feed the plan to Wuji's policy
$$\bq^{\text{ref}}_k=\bq\big(\text{plan}[k]\big)\ \ \text{(blended at jumps)}\quad\Longrightarrow\quad \bq^{\text{target}}_k=\bq^{\text{ref}}_k+\rb_k\quad(\text{stage 6})$$

The planner only decides which frame to track next. The low-level work is exactly Wuji's policy.

Step 9.5 Re-match only when the pen is lost
$$\text{lost}\iff\lVert\bp^{\text{sim}}_k-\bp^{\text{ref}}_k\rVert>\hl{3\ \text{cm}}\ \ \lor\ \ \arccos\big(\bn^{\text{sim}}_k\cdot\bn^{\text{ref}}_k\big)>\hl{40^\circ}$$

Step 9.6 Without a goal loop: escape before a clip ends

Step 10.1 Collect expert data
$$\bo^{\text{BC}}_k=\big[\bq_k,\ 0.25\,\dq_k,\ \be_k\big]\in\mathbb R^{\hl{46}},\qquad \Delta\bq_k=\bq^{\text{target}}_k-\bq_k$$

200 random walks on the graph are executed with Wuji's policy. Each tick stores what the robot could measure and what the expert commanded. Shape check: $20+20+6=46$. The reference is not in the observation, and that is the point. Result: 30,323 samples.

Step 10.2 Normalise inputs and outputs R3
$$\hat\bo=\frac{\bo-\boldsymbol\mu_o}{\boldsymbol\sigma_o},\qquad \widehat{\Delta\bq}=\frac{\Delta\bq}{\hl{s_{\max}}},\quad s_{\max}=\max|\Delta q|$$

The same z-score idea as stage 2. The outputs are scaled into $[-1,1]$ so the network trains well.

Step 10.3 Fit by least squares
$$\min_{\phi}\ \frac1N\sum_{k=1}^{N}\big\lVert \hl{g_\phi}(\hat\bo_k)-\widehat{\Delta\bq}_k\big\rVert^2$$

This is regression: input $\hat\bo$, target $\widehat{\Delta\bq}$. $g_\phi$ is an MLP 512-512-256 with ELU (Exponential Linear Unit, 指数线性单元) activations, trained for 40 epochs.

Step 10.4 Run it
$$\bq^{\text{target}}_k=\bq_k+\hl{s_{\max}}\,g_\phi(\hat\bo_k)$$

Undo the output scaling and add the result to the current joints. The network is also exported as an ONNX file.

A small error leads to states it never saw (covariate shift, 协变量偏移). The next step is DAgger (Dataset Aggregation, 数据集聚合), with graph + Wuji policy as the expert, or PPO on the route-A clips.

💡 The whole project in three sentences
Wuji's policy already knows how to keep a pen on a reference, but each reference is one finite clip. This project changes only the reference: it links frames of all clips into a graph and keeps only the links that Wuji's own policy can execute in simulation. The controller then picks the reference from the hand's state instead of the clock, so it can start anywhere and loop forever.
